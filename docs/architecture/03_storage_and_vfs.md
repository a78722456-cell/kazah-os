# KAZAH Architecture Specification (KAS) — 03. Storage Subsystem & Virtual File System (VFS)

**Статус:** Официальная спецификация (v0.1.0-draft)  
**Компоненты:** Storage Management Framework (Phase 8.6), Virtual File System (Phase 9)

---

## 1. Обзор архитектуры хранения данных

Архитектура хранения данных KAZAH OS спроектирована как многоуровневая, модульная и транзакционная система. В отличие от традиционных монолитных ОС (где драйвер блочного устройства напрямую привязывается к файловой системе), в KAZAH OS реализована строгая иерархия абстракций:

```
[ Физическое устройство хранения ] (AHCI SATA, NVMe, RAMDisk)
               │
               ▼
      [ StorageDeviceObject ]  (Device ID, Vendor, Capacity, BlockSize)
               │
               ▼
       [ PartitionObject ]      (GPT / MBR, Offset, Length, Type UUID)
               │
               ▼
         [ VolumeObject ]       (Logical Volume, LVM, RAID, Encrypted)
               │
               ▼
     [ VirtualVolumeObject ]    (Snapshots, CoW, Universal State Engine)
               │
               ▼
    [ Virtual File System (VFS) ] (Vnode Tree, Mount Manager)
         ┌─────┴──────────────┐
         ▼                    ▼
     [ TmpFS ]            [ DevFS ] (Динамический /dev)
```

## 2. Storage Management Framework (Phase 8.6)

### 2.1. Объектная модель подсистемы хранения
Каждый элемент хранилища зарегистрирован в глобальном реестре объектов как полноправный `KernelObject`:
- **`StorageObject`**: Базовая абстракция блочного устройства. Поддерживает синхронный и асинхронный I/O через `read_blocks` и `write_blocks`.
- **`StorageDevice`**: Представляет физический контроллер или эмулированный диск (например, Ring 3 драйвер `ahci` или `ramdisk`).
- **`VolumeObject`**: Логический том с поддержкой управления правами (Security Descriptor) и состояниями.

### 2.2. Изоляция драйверов блочных устройств
Драйверы жестких дисков (AHCI, NVMe) выполняются в пользовательском пространстве (Ring 3). Контроллер диска взаимодействует с ядром через:
1. Выделенный регион DMA-буфера.
2. Синхронные каналы KazIPC для передачи команд чтения/записи.
3. Supervisor: падение драйвера диска приводит к автоматическому переподключению драйвера менеджером `driver_manager` без повреждения буферов в ядре.

## 3. Virtual File System (VFS) (Phase 9)

### 3.1. Архитектура VFS
VFS абстрагирует файловые операции и предоставляет единое иерархическое дерево каталогов, независимое от типа файловой системы.

#### Ключевые компоненты:
1. **`Vnode`**:
   Внутренняя структура узла файловой системы (файл, каталог, блочное устройство, пайп). Хранит метаданные, размер, права доступа и указатель на операции конкретной ФС.
2. **`FileObject` (Open File Descriptor)**:
   Полноправный `KernelObject`, создаваемый при вызове `sys_open`. Содержит:
   - Указатель на `Arc<Vnode>`.
   - Текущую позицию курсора (offset / seek pointer).
   - Режимы открытия (Read, Write, Append).
   - Дескриптор безопасности процесса-владельца.
3. **`MountManager`**:
   Управляет точками монтирования (`/`, `/dev`, `/system`, `/data`). Разрешает пути (Path Resolution), прозрачно пересекая границы файловых систем.

### 3.2. Встроенные реализации ФС

#### TmpFS (In-Memory RAM File System)
- Смонтирована в корень `/` по умолчанию.
- Поддерживает динамическое создание файлов и каталогов в оперативной памяти.
- Структура каталогов построена на эффективных `BTreeMap`, а содержимое файлов хранится в непрерывных блоках с автоматическим расширением.

#### DevFS (Device File System)
- Смонтирована в `/dev`.
- Динамический синтетический прокси для `STORAGE_REGISTRY`.
- При подключении нового диска или тома (например, `ramdisk` или `ahci0`), в `/dev` автоматически материализуется соответствующий узел (например, `/dev/storage1`), доступный через стандартные системные вызовы `read`/`write`.

## 4. Системные вызовы VFS

| Syscall ID | Имя | Аргументы | Описание |
| :--- | :--- | :--- | :--- |
| **19** | `sys_open` | `path: *const u8, len: usize, flags: u32` | Открывает/создает файл и возвращает handle |
| **20** | `sys_read` | `handle: u32, buf: *mut u8, count: usize` | Чтение данных с проверкой Security Token |
| **21** | `sys_write` | `handle: u32, buf: *const u8, count: usize` | Запись данных в файл/устройство |
| **22** | `sys_close` | `handle: u32` | Закрытие handle и освобождение `FileObject` |
| **23** | `sys_mkdir` | `path: *const u8, len: usize` | Создание директории в целевой ФС |
| **24** | `sys_mount` | `source, target, fstype` | Подключение ФС в точку монтирования |

Все операции проверяются подсистемой `AccessManager` (Biba Mandatory Access Control и DAC ACL).
