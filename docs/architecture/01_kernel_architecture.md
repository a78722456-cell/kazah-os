# Kernel Architecture: Micro-Hybrid & Service Mesh

## 1. Введение в Micro-Hybrid Architecture

Исторически операционные системы делятся на две большие категории по архитектуре ядра:
- **Monolithic (Монолитные)**: Linux, FreeBSD. Все компоненты (драйверы, ФС, сеть) работают в едином адресном пространстве уровня ядра (Ring 0). Быстро, но крайне уязвимо к багам в драйверах.
- **Microkernel (Микроядра)**: MINIX, QNX. В Ring 0 находится только абсолютный минимум (IPC, базовое планирование). Всё остальное — пользовательские процессы. Очень безопасно, но медленнее из-за накладных расходов на контекстные переключения.

**KAZAH OS использует концепцию Micro-Hybrid Architecture (MHA).**
Это эволюционное развитие идей микроядра и гибридного ядра (подобного Windows NT/XNU), спроектированное для максимальной безопасности и отказоустойчивости без критической потери производительности.

## 2. Уровни (Layers)

Архитектура разделена на строгие слои с односторонней зависимостью.

### Layer 0: Boot & Initial Trust
- **UEFI Native Boot**: Загрузка напрямую через UEFI (для Production).
- **Secure Boot & Measured Boot**: Криптографическая проверка цепочки загрузки с использованием TPM. Ядро загружается только если его хэш и подпись верны.

### Layer 1: The Micro-Hybrid Core (Ring 0)
В нулевом кольце защиты выполняется только самый доверенный, математически и логически выверенный код.
Основной язык Layer 1 — **Rust**, гарантирующий отсутствие data races и memory corruption уязвимостей (use-after-free, buffer overflow). Специфичный низкоуровневый код (Context Switch, SIMD-saving) написан на ассемблере x86_64.

**Компоненты Layer 1:**
1. **Scheduler (Планировщик)**: Управление потоками и ядрами CPU (включая NUMA, SMT, Hybrid CPU типа P-Cores/E-Cores).
2. **Memory Manager (MM)**: Выделение физических страниц памяти, управление таблицами страниц процессора (Paging).
3. **IPC Engine (Межпроцессное взаимодействие)**: Быстрая и безопасная передача сообщений между процессами. Это сердце ОС, так как всё построено на обмене сообщениями.
4. **Security Engine**: Базовый модуль изоляции процессов и проверки capabilities.

Всё остальное из ядра вынесено!

### Layer 2: System Service Mesh (Ring 3)
Здесь находится "тело" операционной системы. 
Традиционные подсистемы ядра реализованы как набор изолированных сервисов (демонов) в пространстве пользователя (Ring 3). Они общаются друг с другом и с Layer 1 через высокоскоростной IPC.

**Примеры системных сервисов (System Services):**
- VFS Service (Виртуальная файловая система)
- KazNet Service (Сетевой стек)
- Audio Service
- USB Service
- Graphics Compositor Service

**Преимущества Service Mesh:**
- **Отказоустойчивость (Instant Recovery)**: Если падает `Audio Service` или драйвер видеокарты, система не уходит в BSOD (Критическую ошибку). Падает только этот сервис. Layer 1 (Ядро) замечает падение, собирает дамп для AI Debugger и мгновенно перезапускает сервис. Пользователь видит лишь миллисекундное моргание экрана.
- **Обновление на лету (Atomic Updates)**: Можно обновить сетевой стек, просто перезапустив его процесс, без перезагрузки компьютера.
